# 网络常识补充
***
常见的物理网络设备: 路由器. 交换机 网卡 光猫

## 路由器
***
"路由"(route), 顾名思义: 网络寻址的设备. 
作为局域网 和 公网的转接节点. 

> 为什么还需要交换机呢? 
```
路由器 交换机这俩经常一起出现, 都是在局域网中不可缺少的物理设备, 我有个问题, 为什么路由器不能兼顾交换机的功能呢? 我访问局域网内的设备, 通过路由器也可以判断是外网还是局域网IP
```
答: 
**路由器可以兼顾交换机的功能**, 家用的路由器一般就有这个功能
但 互联网 其实是大大小小的局域网组成, 家里的设备比较少, 路由器可以兼顾, 一旦到了比较多设备的局域网中, 就需要分层去处理. 路由器, 本质是处理"第三层-网络层". 也叫"三层路由", 主要处理IP协议数据的.
而"二层-数据链路层"通常就是由交换机专门处理. 
"二层交换"也就是这么个意思.
数据链路层, 锚定的是"MAC地址"也就是具体设备了, 而不是哪个局域网了.

路由器有: WAN LAN两个口. 
LAN: `Local Area Network` 局域网
WAN: `Wide Area Network` 广域网

## 交换机
***
属于"数据链路层"的物理设备. 用于数据在局域网内的分发. 
**以太网**: 局域网怎么通信的技术规范. 
交换机平时处理的核心东西, 就是**以太网帧**
```
Ethernet Frame
┌────────────┬────────────┬──────────┬─────────┐
│ 目标 MAC   │ 源 MAC     │ 类型     │ 数据    │
└────────────┴────────────┴──────────┴─────────┘
```
以太网在前期网络的应用中得到普及, 就成为了数据链路层的规范(WIFI用的不同协议).
因特网: `networks of network`, 网络与网络的通信. 
以太网: `Ethernet` 局域网的通信规范.
路由器通过`IP`处理数据流向
交互机通过`MAC`处理数据流向网卡设备.

## 三次握手
***
第一次握手: 发送方`SYN=1 seq=x`
第二次握手: 接收方`ACK=1 ack=y SYN=1 seq=x+1`
第三次握手: 发送发`ACK=1 ack=y+1`
`seq`: 序号32bit, 第一次是个随机数
`ack`: 确认号32bit, 由接收方给出.

关于为什么要三次握手的理解:
TCP设计的初衷就是要双向的可靠传输: **我发的你能收到, 你发的我也能收到**
日常举例: A B两个人打电话
A: 喂,听得到吗?
B: 听得到, 你呢?
A: 我也听得到
省略后面的内容...
其实我们打电话一直都是秉承这TCP三次握手的原则.

### 三次握手,内核层, socket的状态变化
***
发送方/客户端(client):
```
CLOSED
  ↓ connect()
SYN_SENT
  ↓ 收到 SYN+ACK，并发出 ACK
ESTABLISHED
```
接收方/服务端(server):
```
CLOSED
  ↓ socket + bind + listen
LISTEN
  ↓ 收到客户端 SYN
SYN_RECV
  ↓ 收到客户端最后一个 ACK
ESTABLISHED
```

合起来:
```
客户端                         服务端

CLOSED                         LISTEN
   |                              |
   | SYN                          |
   |----------------------------->|
SYN_SENT                       SYN_RECV
   |                              |
   |        SYN + ACK             |
   |<-----------------------------|
   |                              |
   | ACK                          |
   |----------------------------->|
ESTABLISHED                  ESTABLISHED
```

## 四次挥手
***
```
那四次挥手, 我就再以打电话为例:
A: 我聊完了 我挂了哦
B: 好, 我想想还有没有想聊的
B: 我这儿也没了
A: 好.
嘟嘟嘟...
```
第一次挥手: 发送方FIN:1 seq=x
第二次挥手: 接收方ACK:1 seq=y ack=x+1
第三次挥手: 接收方FIN:1 seq=y ack=x+1
第四次挥手: 发送方: ACK:1 ack=y+1 seq=x+1
`ACK`不占序列号.

### 四次挥手的socket状态变化
***
主动关闭方, 在代码上直接调用close函数就行, 后续是由内核来完成
被动关闭方, recv函数收到的bytes为0就表示断开连接, 此时需要主动调用close函数.
主动关闭方:
```
ESTABLISHED
   ↓ close()
FIN_WAIT_1
   ↓ 收到 B 的 ACK
FIN_WAIT_2
   ↓ 收到 B 的 FIN，并回复 ACK
TIME_WAIT
   ↓ 等待一段时间
CLOSED
```

被动关闭方:
```
ESTABLISHED
   ↓ 收到 A 的 FIN，并回复 ACK
CLOSE_WAIT
   ↓ 应用程序也调用 close()
LAST_ACK
   ↓ 收到 A 最后的 ACK
CLOSED
```

完整过程:
```
A 主动关闭                      B 被动关闭

ESTABLISHED                   ESTABLISHED

A close()
内核发送 FIN
    | FIN
    |---------------------------->
FIN_WAIT_1                   收到 FIN
                             内核回 ACK
                             CLOSE_WAIT

    |        ACK
    |<----------------------------
FIN_WAIT_2

                             B 的应用调用 close()
                             内核发送 FIN
    |        FIN
    |<----------------------------
收到 FIN
内核回 ACK
TIME_WAIT                    LAST_ACK

    | ACK
    |---------------------------->
                             收到 ACK
                             CLOSED
```

# UDP

Users Datagram protocol

## 什么是有连接 无连接
***
有连接: 发送数据前, 需要双方确认
无连接: 发送数据前, 不需要确认对方状态. 

UDP不保证数据的准确性, 这是在传输层数据处理. 但是我们可以在应用层进行封装判断.
