1、什么是高可靠通信？
```
数据准确 不错序 不重复. 通过超时重传等机制确保数据准备送达的通信
TCP就是典型的可靠通信.
```

```
高可靠通信就是保证数据尽量不丢、不重、不错序，并通过确认和超时重传等机制保证数据最终正确到达。
```

2、TCP与UDP的区别有哪些？UDP如何实现可靠传输？
```
TCP 是面向连接、可靠、有序的字节流协议，通过 ACK、序列号、超时重传、流量控制等机制保证可靠传输。UDP 是无连接的报文协议，不保证到达、顺序和去重，开销更小。
UDP 如果需要可靠性，可以在应用层加入序列号、ACK、超时重传、去重等机制。
```

3、如何区分A、B、C、D类地址
```
A、B、C、D 类地址可以根据 IP 地址最高几位判断，分别是 0、10、110、1110。传统分类地址中 A、B、C 类对应不同长度的网络号，D 类用于组播。现代网络主要使用 CIDR，通过 IP 地址和子网掩码或前缀长度确定网络位和主机位，可以更灵活地分配地址，减少浪费。
```

4、IPv4与IPv6的区别是什么？（参考面试宝典）
```
1. 地址长度不同。IPv4 是 32 位，IPv6 是 128 位，地址空间极大。
2. 首部结构不同。IPv6 基本首部更固定、更简化，一些可选功能放到了扩展首部里，路由器处理起来更规整。
3. 通信方式不同。IPv4 支持单播、广播、组播；IPv6 取消了广播，主要使用单播、组播和任播。
4. 地址配置方面，IPv6 对自动配置支持更完善，例如 SLAAC。
5. IPv6 不再使用 IPv4 那种首部校验和，分片机制也有所变化。
```

5、什么叫长连接？什么叫短连接？（参考面试宝典）
```
长连接是在一次 TCP 连接建立后持续进行多次数据交互，减少重复握手和挥手的开销，适合频繁通信场景。短连接通常完成一次或少量请求后就关闭，能够减少长期占用连接资源，但频繁通信时建立连接的成本更高。
```

1、简述三种超时检测的办法
```
Socket 超时检测常见有三种方式：通过 `setsockopt` 设置 `SO_RCVTIMEO/SO_SNDTIMEO`；通过 `select/poll/epoll_wait` 的超时参数检测；或者使用 `alarm`、`timerfd` 等定时器机制自行维护超时。
```

2、什么是粘包？如何解决粘包带来的问题
```
TCP 是面向字节流的协议，不保留应用层消息边界，所以一次 `send()` 的数据可能被多次 `recv()` 读取，多次 `send()` 的数据也可能被一次 `recv()` 一起读取，这就是常说的粘包和拆包问题。解决方法是在应用层定义消息边界，例如固定长度、分隔符或者“消息长度 + 消息体”的协议格式。
```


3、解释以下名词含义，并说明其作用

• IP

• port

• 子网掩码（如何通过子网掩码制订当前网络下最多连多少台主机）

• DNS服务器

• DHCP服务器

• 广播与组播
```
IP：Internet Protocol，互联网协议，主要负责网络层寻址和路由。IP 地址用于标识网络中的主机或接口，常见有 IPv4 和 IPv6。

Port：端口用于区分一台主机上的不同网络通信端点。IP 可以确定主机，端口可以进一步确定具体应用或 Socket。TCP 和 UDP 的端口空间彼此独立。

子网掩码：用于区分 IP 地址中的网络位和主机位。例如 `/24` 表示前 24 位是网络位，后 8 位是主机位，所以总共有 `2^8 = 256` 个地址。普通情况下去掉网络地址和广播地址，可用主机地址为 `254` 个。

DNS 服务器：负责域名解析，把类似 `www.example.com` 的域名转换成对应 IP 地址，方便主机找到目标服务器。

DHCP 服务器：负责自动给主机分配网络配置，比如 IP 地址、子网掩码、默认网关和 DNS 服务器。设备接入网络后，通常通过 DHCP 自动获得这些参数。

广播：把数据发送给同一广播域中的所有主机。

组播：把数据发送给加入某个组播组的主机，只有对该组播感兴趣的设备才接收和处理。
```

1、说出OSI七层协议模型，并简述各层的功能
```
1. 物理层：负责比特流在物理介质上的传输，关心电信号、光信号、接口、网线、光纤等。
2. 数据链路层：负责同一链路或局域网内的数据传输，以帧为单位，典型涉及 MAC 地址、以太网、交换机。
3. 网络层：负责跨网络寻址和路由选择，典型协议是 IP，典型设备是路由器。
4. 传输层：负责端到端的数据传输，典型协议是 TCP、UDP，涉及端口、可靠传输、流量控制等。
5. 会话层：负责建立、维护和结束通信双方的会话。
6. 表示层：负责数据格式转换、编码、压缩、加密解密等，让双方能够正确理解数据。
7. 应用层：直接为应用程序提供网络服务，例如 HTTP、FTP、DNS、SMTP 等。
```

4、TCP如何判断对方异常断电？
```
对方异常断电时不会正常发送 FIN，因此本机 TCP 无法立即感知。如果继续发送数据，TCP 会因为收不到 ACK 进行重传，超过重传次数后判断连接异常。如果连接长期没有数据交互，可以开启 TCP Keepalive，或者在应用层使用心跳机制检测对端是否存活。
```

5、当客户端连不上服务器时，如何排查错误？
```
先检查 `connect()` 返回值和 `errno`，再确认服务器是否启动并监听正确 IP 和端口，然后检查客户端目标地址、网络连通性、路由和防火墙。最后可以通过 `ss`、`ping`、`tcpdump` 或 Wireshark 抓包，观察 TCP 三次握手停在哪一步，从而定位问题。

第一层，网络接口层，也就是物理层和数据链路层。检查网线、Wi-Fi、网卡、交换机是否正常，网卡是否启用，链路是否建立。可以看 `ip link`、`ifconfig` 等信息。

第二层，网络层。检查 IP 地址、子网掩码、默认网关、路由是否正确，目标主机是否可达。可以用 `ping`、`ip route`、`traceroute` 等工具。

第三层，传输层。检查 TCP 端口是否正确，服务器是否在监听，三次握手是否成功，是否被防火墙拦截。可以看 `connect()` 的返回值和 `errno`，用 `ss`、`netstat`、Wireshark 或 `tcpdump`。

第四层，应用层。TCP 已经连上，但业务还是不能正常通信时，就检查客户端和服务器程序逻辑，例如协议格式是否一致、是否发错数据、服务器是否正确处理请求。
```

1、二层交换机的工作原理？
```
二层交换机根据 MAC 地址转发以太网帧。交换机通过收到帧的源 MAC 学习 MAC 地址和端口的对应关系，并维护 MAC 地址表。收到帧后查询目的 MAC，如果表中有对应端口，就定向转发；如果不知道目的 MAC 在哪个端口，就进行泛洪。广播帧也会向同一广播域内其他端口转发。
```
2、简述任意两种并发服务器的设计，并说明其优缺点以及容易出现的问题
```
多进程服务器通常由父进程 `accept`，子进程处理客户端。优点是隔离性好，缺点是创建和切换开销较大，需要注意关闭父子进程中不需要的文件描述符以及回收子进程。多线程服务器通常由主线程接收连接，工作线程处理客户端。优点是资源开销较小、共享数据方便，缺点是共享资源容易发生竞争，需要做好线程同步，并避免死锁等问题。
```

3、简述三种IO多路复用方法以及各自的特点
```
`select`、`poll`、`epoll` 都属于 IO 多路复用。`select` 使用位图管理 fd，数量受限，并且每次都要拷贝和遍历全部 fd；`poll` 使用 `pollfd` 数组，取消了固定数量限制，但仍需要每次拷贝并遍历全部 fd；`epoll` 把 fd 注册到内核，等待时只返回就绪事件，更适合大量连接和高并发场景。
```

1、简述五种IO模型，并说明是同步操作还是异步操作
```
五种 IO 模型分别是阻塞 IO、非阻塞 IO、IO 多路复用、信号驱动 IO 和异步 IO。前四种都属于同步 IO，因为最终的数据读写仍需要应用程序主动发起系统调用；异步 IO 由内核完成等待和数据拷贝，完成后再通知应用程序，因此属于异步 IO。
```
2、路由器的工作原理？简述数据包发送出去的流程
```
路由器工作在网络层，收到数据包后根据目标 IP 查询路由表，选择合适的下一跳和出口接口，再重新进行二层封装并转发。主机发送数据时，先判断目标 IP 是否在同一子网，如果在同一子网就直接发送；如果不在，就把数据交给默认网关，由路由器逐跳转发，直到到达目标网络。
```
