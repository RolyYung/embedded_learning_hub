# 项目 6：迷你嵌入式设备模拟器

最终项目包含应用层、驱动层、工具模块和两个独立测试程序。驱动和工具模块应组成一个静态库，应用及测试再按需要链接它。

## 基础任务

1. 生成静态库 `build/libdevice.a`。
2. 生成应用 `build/device_simulator`。
3. 分别生成 `build/test_device` 和 `build/test_checksum`。
4. `test` 目标应构建并运行全部测试；任一测试失败时，构建应失败。
5. 提供 `all`、`run`、`test`、`clean`、`help` 目标。

## 改进任务

1. 使用模式规则管理多个源码目录到 `build/obj/` 的路径映射。
2. 编译时自动生成 `.d` 依赖文件，并在后续构建中加载它们。
3. 加载首次构建时尚不存在的依赖文件，不应产生错误。
4. 正确处理自动生成依赖文件中已经被删除或改名的头文件。
5. 编译规则使用 `$@`、`$<`；归档和链接规则使用 `$@`、`$^`。

## 挑战任务

1. 同时支持 Debug/Release，并隔离全部产物。
2. 使用并行构建，检查是否存在因目录未创建而偶发失败的依赖问题。
3. 新增 `check` 目标：启用更严格的警告，并把警告视为错误。
4. 增加必要的配置检查，缺失关键变量时输出清晰错误。
5. 比较“递归调用子目录 Makefile”和“一个 Makefile 管理全项目”两种组织方式；本次先实现后一种并写下优缺点。

## 自动依赖实验

完成 `.d` 文件支持后，依次进行：

1. 修改 `include/device.h`，观察应用、驱动及设备测试哪些对象被重编译。
2. 修改 `include/checksum.h`，观察无关设备对象是否保持不变。
3. 修改 `utils/checksum.c`，观察静态库、应用及两个测试中哪些目标更新。
4. 不修改任何文件再次构建，确认没有多余命令。

## 验收

- 应用依次显示 READY、三个处理结果、校验和 `0xA0`、处理数量 3 和 OFF。
- 两个测试程序都输出 `PASS`。
- 头文件改变后，相关对象能通过自动依赖准确重建。
- `make -j` 多次执行均稳定成功。
- 构建目录可整体删除，并能从零恢复。

## 本项目知识点

复杂目录映射、静态库、多可执行目标、自动生成并加载依赖、测试目标、并行构建、条件配置、`$@`、`$<`、`$^`。
