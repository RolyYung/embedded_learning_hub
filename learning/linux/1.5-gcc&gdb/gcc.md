
#gcc  #C语言编译 #Makefile 

> GCC (GNU Compiler Collections). 起初用于编译C语言, 后面可以用于编译C++,JAVA等.

常用的命令:
```bash
gcc main.c -o main.ext
```

Linux 系统下,gcc是预装软件,不需要额外安装. windows下需要额外安装和配置环境变量.
# 经常会看到的文件后缀
1. `.c` C语言源文件
2. `.cpp` C++源文件
3. `.h` 头文件
4. `.o` 经过编译但还没有链接的文件
5. `.a` 文件目标文件`.o`生成的静态库文件
6. `.so`动态库文件

# gcc编译过程
## 默认处理
`gcc hello.c`
> 直接 `gcc` 接文件名就会直接编译出可执行文件, 由于没有规定输出的文件名,所以默认会生成出一个`a.out`文件
> 在工作中一般不会这么去处理.

`gcc hello.c -o target`
> `-o`后面接文件名就表示输出的可执行文件名.
> `-o`的记忆法就是output, 输出. 

## C语言程序编译的四个步骤
### 1. 预处理
`gcc -E source.c -o prev.i`

> 选项 `-E` 就是预处理的意思, 产出的又是后缀`.i`文件,这个怎么记忆呢?
答: E: expand 展开操作. 中文意思的预处理是方便我们理解, 但实际代码执行上就是对头文件,宏定义等进行展开处理. .i文件的理解就是中间文件的意思. 

### 2. 编译
`gcc -S prev.i -o huibian.s`

记忆点:
> 汇编: Assemble. 产出的源代码文件 assemble source. 所以都是s相关.

### 3. 汇编
`gcc -c huibian.s -o hello.o`

> `-c` 选项会自动输出编译的文件名,并将后缀改成.o

例子: `gcc -c huibian.c`
产出: `huibian.o`

记忆点:
> c: compile 将产出的汇编代码编译成目标文件. 

在这个阶段下, 产出的.o文件是很重要的, 它已经是二进制文件了, 可以把它理解为一个项目零件了, 不像前面几个阶段产出的.i .s文件,只是中间形态,这个即可以自己用, 也可以作为大项目中的一部分去执行.后面Makefile也会经常碰到这个.

### 4. 链接
将产出的.o文件链接形成最后的可执行文件. 学习初期可能只会碰到一个. 但真正做到项目里去了, 就会发现需要链接多个文件和代码. 这个后面再去深究.

# 其他选项
## -Wall
开启常见的警告信息. 
>发现代码中的潜在问题, 提高代码质量

理解:
W: `warning`
all: 所有, 这里指大部分常见的错误信息.
在选项中还有其他的`-WXXX`的选项, 如`-Wextra` `-Werror` 都是先把W拆开, 然后看后面单词理解其意义.

## -g
gdb调试的意思. 用于代码执行的调试, 查看代码细节, 追踪代码问题.

## -std
指定标准. 如:
`gcc -std=c99 hello.c`
以99版C语言标准去编译hello.c文件.

# 多文件编译
1. 只需要编译`.c`文件
2. 头文件如果不在根目录下, 就需要带上`-I [directory path]`
