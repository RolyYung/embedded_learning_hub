# 缓冲区
***
缓冲区设置的目的: 多次硬件层的操作, 整理到一次去执行.
硬件层中也有缓冲区的概念,这里做个大致的解释:
> 在做文件读取操作时(以`fgetc`为例), 硬件层接收了读取操作, 并不会一个一个的读取, 而是一次性读取很多个数据(512字节的倍数). 这种操作被称为"预读", 然后依次把值传递给应用层. 但具体的实现暂时还不深究.

# 标准IO
***
标准IO都是调用C语言的库函数, 可移植性比较好, 不用关心每个系统底层IO的操作. 只要支持系统C语言,那么就可以操作.

## 流(stream)
***
标准IO操作文件, 都是通过字节流(stream)这个概念来操作.
具体的实现, 是由FILE这个结构体来实现. 根据教程我们已经完成了tags的安装, 可以通过`vim -t FILE`来查看FILE这个结构的具体实现 和 它名下的成员.

## `printf`函数及其衍生
***
	`int printf(const char * format, ...)`
返回值int: 失败就会返回一个负数, 成功就会返回输出打印的成员数量
参数1: format, 字符串. 
参数`...`: 用来表示不定长参数, 也就是不确定后面会传多少个参数, 可能是0, 可能是很多很多. 在我们平时的编程中, 很少用到. 等用到了再去深究其用法.

	`int fprintf(FILE * stream, char * format, ....)`
返回值和上面一样, 把输出的字符串放到传入的流中, 而不是终端中.
前缀带`f`的一般都会是标准IO的库函数. `f`就是file的意思, 操作文件的意思.
	`int snprintf(char * str, int size, char * format, ...)`
把字符串赋值到传入的字符串中, size规定字符串大小.

## 常见的日志记录的参数
***
时间;日期;代码行数;函数名等
***
这里老师提到了一个新的知识点: 
有一些宏: `__TIME__; __DATE__; __LINE__; __func__; __FILE__`

我们在这里去深究一下这些宏在哪里定义, 为什么可以使用.

### 预定义宏
***
上面这些都是预定义宏.
预定义宏是C语言标准中规定的. 每个编译器都需要实现这些宏, 在预处理阶段需要提供和处理这些宏. 
比较特殊的是`__func__ ` 它虽然不是严格意义上的宏, C语言标准要求每个函数在执行前都需要补充这个`__func__`字符串, 保证每个函数下都能够调用.具体怎么实现, 可以由编译器自由编写, 只要功能满足即可.


| 预定义宏       | 值        | 备注      |
| ---------- | -------- | ------- |
| `__TIME__` | 文件编译的时间  | 不是当前的时间 |
| `__DATE__` | 文件编译的日期  | 同上      |
| `__LINE__` | 调用时对应的行数 |         |
| `__FILE__` | 当前文件名    |         |
| `__func__` | 当前调用的函数名 |         |

# 日志信息登记
***
c语言中一般是氛围四个
1. DEBUG: 调试信息
2. INFO: 状态改变, 打印关键信息
3. WARN: 不影响程序运行的异常
4. ERROR: 影响程序运行的异常
