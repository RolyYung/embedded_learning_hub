2. fork 函数如何使用？为何fork的返回值如此设计？  
	引入必要的头文件后,直接调用fork函数, 用一个`pthread_t`的变量去接(例子:`pid`);然后判断`pid`的值, fork成功后, fork后的代码会执行两遍, 如果`pid > 0`代表是父进程, `pid == 0`是子进程
	返回值设计: 1. linux提供的进程id函数只有`getpid``getppid`, 父进程无法只知道当前创建的子进程id, 这时候返回子进程id方便父进程记录. 子进程则不需要, 可以通过`getppid`获取父进程id 2. 一个pid=0 一个大于0方便后续判断操作, 如果都大于0就还需要加一层判断
3. 什么是虚拟地址？有什么作用？
	linux通过虚拟地址->MCU->物理地址, 来完成虚拟地址到物理地址的映射, 每个进程都是有4G的虚拟内存,而不是真实的物理地址. 原因是: 物理地址没有做好地址隔离, 进程可以随意访问不属于它的物理地址, 有风险. 通过虚拟地址->MCU的控制,能很好判断是否访问了非法地址.保护计算机安全.
	作用: 可以根据进程的需要, 安排合理的物理内存空间使用. 进程与进程之前的安全隔离.

### 10分题
1. 简述写实拷贝技术 与 计数技术 
```
答: 写时拷贝出现在进程fork后, 不会立即开辟一个新的物理地址空间给子进程,而是两个进程共用同一个物理地址空间, 直到子进程有写入操作时才会拷贝一份,开辟新的物理空间给子进程. 能有效的解释内存空间
计数技术: 是不是指的文件引用计数? 文件引用计数就是在进程每次open打开文件, 都会增加文件的引用计数, 用于判断目前是否有进程在打开文件, 在管道中就可以很好的判断读端 写端是否打开,确保管道通信准确性 安全性
```
1. 为何进程需要有僵尸态？描述几种僵死子进程回收的方法。 
```
进程在系统有信息配置, 在退出后, 需要进行回收避免造成内存资源浪费, 而僵尸态就是进程实际已经死了,但系统的信息未移除的状态.
回收方式: 资源回收函数: wait waitpid等, 父进程通过资源函数回收.
通过杀死父进程, 系统进程进行回收后处理, 系统进程会定期处理僵尸进程
```
1. 线程的属性有哪些？他们有什么区别？如何设置线程的属性？  
```
属性有:结合态(joined) 分离态(detached)
结合态线程退出后, 可以回收. 分离态不会退出后, 不会通知其他线程, 自动被系统回收.
设置属性: pthread_attr_init() pthread_attr_t attr变量. 也有宏PTHREAD_ATTR_IN..来静态设置.
也可以动态设置: pthread_detach函数
```

1. 守护进程的功能是什么？如何创建守护进程？  
```
功能是提供系统级别的功能, 脱离终端控制, 随系统的生命周期运行
创建:
1. fork一个子进程, 父进程退出exit. (原因: 第二步的setsid不能是组进程组长)
2. 子进程setsid, 创建一个新会话
3. 再fork一个, 父进程退出exit, 子进程作为守护进程(原因: 作为会话组组长的进程, 有可能再次被终端绑定,这次fork就是为了避免这种情况)
4. chdir: 切换工作目录(原因: 防止后续因守护进程持续运行,导致文件目录无法卸载)
5. umask: 修改创建文件权限掩码

```
1. 说出进程的状态，以及状态字符缩写，并描述各状态之间是如何转换的？
```
答: 就绪态, 运行态(R), 睡眠态(S), 不可中断的睡眠态(D), 停止态(T), 僵尸态(Z),死亡态(X)
转换: 就绪态等待CPU时间片到就会切换到运行态
运行态受到SIGSTOP就会进入停止态(T). 收到SIGCON就会继续运行
睡眠态可以通过sleep函数进行
不可中断的睡眠态,大多数情况是在等待硬件类 系统级别的数据准备完成,完成后就会自动切换到运行态
僵尸态就是进程实际已死亡, 但没有进行资源回收(PID等进程信息没被回收,还占用内存资源)
```
