
### 8分题
1. 进程与线程的区别，以及实际什么场景运用它们  
```
进程是资源分配和隔离的重要单位，每个进程具有独立的虚拟地址空间等进程级资源，因此进程之间隔离性较强，一个进程发生异常通常不会直接破坏另一个进程的地址空间。

线程是进程内部的执行单元。同一个进程中的线程共享地址空间、全局变量、堆和文件描述符等资源，但每个线程有自己的栈、寄存器上下文等。

如果任务之间强调隔离，可以考虑多进程；如果多个任务需要频繁共享数据、并发执行，可以考虑多线程。例如服务器可以使用多个线程分别处理不同客户端请求。
```
1. fork 函数如何使用？为何fork的返回值如此设计？  
```
`fork()` 用于创建子进程，返回值类型为 `pid_t`。调用成功后会产生一个子进程，父子进程都会从 `fork()` 之后继续执行，因此通常根据返回值区分父子进程。

`fork()` 失败返回 `-1`；在子进程中返回 `0`；在父进程中返回新创建子进程的 PID。

这样设计一方面可以通过返回值直接区分父进程、子进程和创建失败三种情况，另一方面父进程可以直接获得新创建子进程的 PID，方便后续进行 `waitpid()`、发送信号等操作。子进程如果需要自己的 PID 或父进程 PID，可以通过 `getpid()` 和 `getppid()` 获取。
```
1. 什么是虚拟地址？有什么作用？
```
虚拟地址是进程访问内存时使用的地址，每个进程都有自己独立的虚拟地址空间，虚拟地址通过页表和 MMU 转换为物理地址。它的主要作用是实现进程之间的内存隔离和访问保护，同时让操作系统能够灵活管理物理内存，并支持 COW、mmap、共享内存等机制。
```

### 10分题
1. 简述写实拷贝技术 与 计数技术  
```
**写时拷贝 COW（Copy On Write）：** `fork()` 创建子进程后，父子进程的一些内存页面可以暂时映射到相同的物理页面，并设置相应的保护。当父进程或子进程尝试修改共享页面时，才复制相应页面，使双方拥有各自的副本。这样可以减少不必要的内存复制，提高 `fork()` 的效率并节省物理内存。

**引用计数 Reference Counting：** 是一种资源生命周期管理技术。每增加一个对资源的有效引用，引用计数增加；引用消失时计数减少；当引用计数降为 0 时，说明该资源已经没有使用者，可以进行释放。Linux 内核中的许多对象和资源管理都会使用类似思想。
```
1. 为何进程需要有僵尸态？描述几种僵死子进程回收的方法。  
```
**为什么需要僵尸态：** 子进程退出后，其执行资源已经释放，但内核需要暂时保留 PID、退出状态等信息，让父进程能够通过 `wait()`、`waitpid()` 获取子进程的结束情况。因此在父进程完成回收之前，子进程会处于僵尸状态。

**回收方式：** 父进程可以主动调用 `wait()` 或 `waitpid()` 回收子进程；也可以捕获 `SIGCHLD` 信号，在信号处理逻辑中调用 `wait()` / `waitpid()`；如果父进程退出，未被回收的子进程会由合适的系统进程接管，并最终完成回收。

1. 线程的属性有哪些？他们有什么区别？如何设置线程的属性？  
```
线程具有分离状态、栈大小、栈地址、调度策略等多种属性，使用 `pthread_attr_t` 保存线程属性。

常见的是分离状态。线程默认是 joinable 状态，退出后需要其他线程通过 `pthread_join()` 回收相关资源并可以取得返回值；detached 线程退出后，其相关线程资源会自动释放，不能再通过 `pthread_join()` 回收。

可以先通过 `pthread_attr_init()` 初始化属性对象，再使用 `pthread_attr_setXXX()` 系列函数修改具体属性，最后将属性对象传给 `pthread_create()`。对于已经创建的线程，也可以使用 `pthread_detach()` 将其设置为 detached 状态。
```
1. 线程间有哪些资源是共享的？哪些资源是独有的？
**线程属于同一个进程，所以进程级资源通常共享；维持每条执行流运行所需要的状态，则每个线程独立拥有。**
```

**推荐答案：**

> **共享资源：** 同一进程中的线程共享进程的虚拟地址空间，包括代码段、全局变量、静态变量、堆等，同时共享打开的文件描述符、当前工作目录等进程级资源。
> 
> **独有资源：** 每个线程拥有自己的线程 ID、栈、寄存器上下文、程序计数器、调度相关信息等。线程还具有自己的信号掩码等线程级状态。
> 
> 因为多个线程可以访问相同的共享数据，所以当多个线程同时修改共享资源时，可能产生竞态条件，因此需要 mutex、semaphore 等同步机制。
```

### 13分题
1. 进程间通信有哪些？各有哪些特点？  
```
Linux 进程间通信方式主要有管道、FIFO、信号、System V IPC 和 socket 等。
无名管道 pipe： 是单向字节流，通常用于具有亲缘关系的进程之间通信，例如父子进程。没有文件系统中的名字。
有名管道 FIFO： 同样通过管道传输数据，但在文件系统中具有名字，因此没有亲缘关系的进程也可以通过同一个 FIFO 进行通信。
信号 signal： 主要用于向进程通知某个事件发生，由内核负责信号的递送。进程可以采用默认处理、忽略或捕获处理部分信号。它更适合事件通知。
消息队列 message queue： 内核维护消息队列，进程通过 msgsnd() 和 msgrcv() 发送、接收消息。消息具有边界和类型，可以阻塞或非阻塞操作。
共享内存 shared memory： 多个进程将同一块物理内存映射到各自的地址空间，可以直接读写共享数据，减少数据复制，速度很快，但需要额外的同步机制防止竞争。
信号量 semaphore： 主要用于进程或线程之间的同步与互斥，通常用于控制对共享资源的访问，本身主要解决同步问题。

1. 守护进程的功能是什么？如何创建守护进程？  
```
**功能：** 守护进程 daemon 是一种长期在后台运行、通常脱离控制终端的进程，常用于持续提供系统或应用服务。

**经典创建流程：**

1. `fork()` 创建子进程，父进程退出，使子进程不再是原进程组组长，为后续 `setsid()` 创造条件。
2. 子进程调用 `setsid()` 创建新的 session，脱离原来的会话、进程组以及控制终端。
3. 可以再次 `fork()`，让最终进程不再是 session leader，从而避免它以后重新获得控制终端。
4. 使用 `chdir()` 修改工作目录，经典做法是切换到 `/`，避免长期占用某个文件系统的目录。
5. 使用 `umask()` 设置合适的文件创建权限掩码，使 daemon 创建文件时的权限可控。
6. 关闭不需要的文件描述符，并根据需要重新处理 `stdin`、`stdout`、`stderr`，例如重定向到 `/dev/null` 或日志文件。
```
1. 说出进程的状态，以及状态字符缩写，并描述各状态之间是如何转换的？
```
Linux 常见的进程状态字符有 `R、S、D、T、Z` 等。

**R（Running / Runnable）：** 进程正在运行或者已经处于可运行状态，正在等待 CPU 调度。

**S（Interruptible Sleep）：** 可中断睡眠状态。进程正在等待某个事件或资源，条件满足或者收到适当信号后可以被唤醒。

**D（Uninterruptible Sleep）：** 不可中断睡眠状态，通常出现在等待某些内核 I/O 操作等情况下，等待条件完成后才能继续运行。

**T（Stopped）：** 进程处于停止状态，例如收到 `SIGSTOP` 后进入停止状态，之后可以通过 `SIGCONT` 继续执行。

**Z（Zombie）：** 僵尸状态。子进程已经退出，大部分执行资源已经释放，但退出状态、PID 等少量信息仍由内核保留，等待父进程通过 `wait()`、`waitpid()` 回收。

**X（Dead）：** 死亡状态，一般非常短暂，通常不会在正常 `ps` 输出中观察到。
```
