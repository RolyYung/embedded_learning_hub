# 1、Linux操作系统下各路径存放什么文件？（`usr/dev/opt/etc/home/bin/media`）

## 答: 
1. `/usr`: 各类软件的存放地址. 存放各类程序和配置. 比如终端命令(`/usr/bin`), 头文件(`/usr/include`), 库文件(`/usr/lib`)
2. `/dev`: 各类设备文件, 常用的有鼠标, 键盘, 硬盘,终端
3. `/opt`: 统一存放第三方软件的. 比起一般程序, 可能需要存放到 `/usr` `/lib` `/bin` 下, 也可以统一存放到`/opt`文件夹下, 这样方便后续的删除.
4. `/etc`: 各类配置文件. 最常见的就是`/etc/profile`可以配置系统的环境变量.还有各类软件的配置, 常见的: `apt` , 还有一些系统级别的配置: `bluetooth` `kernel` 蓝牙 内核的配置
5. `/home`: 用户的家目录. 存放各个用户的目录. 用户自己的文件 配置 软件都可以放在这个文件夹下. 我常用的就是`/home/roly` `~/.bashrc` 
6. `/bin`: 各类二进制可执行程序/命令的存放目录. 常用的各种命令`ls` `cp` `mv` `cp` `rm` 都是放在这里. 当然在现代Linux系统下, `/bin` 目录都重定向到了`/usr/lib`目录下了.
7. `media`: 各类媒介, U盘 SD卡 移动硬盘等, 都会自动挂载到这个上面去. 还有一个`/mnt`文件夹, 这个是需要管理员手动去挂载上去的. 我觉得它俩的区别就是一个自动 一个手动.

## AI建议答案:
```markdown
/usr：存放大量用户空间程序及其共享数据。例如 /usr/bin 存放普通命令，/usr/lib 存放库，/usr/include 存放头文件。
/dev：存放设备文件，也就是访问设备的接口。例如磁盘、终端等设备对应的设备文件。
/opt：主要用于安装附加的第三方软件，通常可以把一个软件相关的文件集中放在 /opt/软件名 下。opt 可以记成 optional。
/etc：主要存放系统级和软件的配置文件。例如 /etc/profile、APT 的配置等。可以把 /etc 和“系统配置”关联起来记。
/home：普通用户的家目录。例如用户 roly 的家目录通常是 /home/roly，用户自己的文件和个人配置通常放在这里。root 的家目录通常是 /root。
/bin：传统上存放基本的用户命令，例如 ls、cp、mv、rm。现代很多 Linux 发行版采用 merged /usr，因此 /bin 常常是指向 /usr/bin 的符号链接。
/media：主要作为 U 盘、SD 卡、移动硬盘等可移动介质的挂载位置，桌面 Linux 经常自动在这里创建挂载点。/mnt 则主要作为管理员临时挂载文件系统的位置。
```

# 2、Linux 操作指令：
- 查看文件前5行
- 查看文件后5行 且实时查看
- 搜索文件是否包含特定内容
- 压缩与解压文件
- 创建软连接与硬链接
- 如何修改某网卡的ip地址

## 答: 
1. `head -5 main.c`
2. `tail -5 -f main.c`
3. `grep -e "main()" -f main.c` 查看`main.c`文件内是否有`main()`字符串
4. `tar` 命令: 压缩: `tar -cvf main.tar main.c hello.c`; 解压: `tar -xvf main.tar`
5. `ln` 命令: 软链接: `ln -s target.c main.c` 给main.c文件创建软链接文件target.c; 硬链接: `ln target.c main.c`
6. `nmcli connection modify`

例子: 修改名字为`ssh_ip`ip地址
`nmcli connection show`
`nmcli connection modify ssh_ip ipv4.address 192.168.1.100/24 ipv4.gateway 192.168.1.1 ipv4.dns 8.8.8.8 ipv4.method manual`

`192.168.*.*` 这是`ipv4`规定的私有网络ip, 也就是局域网的ip地址.
子网掩码的作用就是告诉你前几位是网络地址, 后几位是主机位

网关就是负责去和外面对接的, 默认就是192.168.1.1; 如果是自己局域网内的互相访问, 就不需要用到网关. 如果是局域网之外的, 就会把数据交给网关, 由网关来负责外面的联络

`dns` 域名解析, `8.8.8.8`是谷歌提供的dns服务器地址, 非常好记. cloudflare也有`1.1.1.1`. 所以这个无所谓. 知道几个常用的就行.

# 3、软连接与硬链接的区别
## 答:
1. 软链接, 不同的inode, 一旦源文件被移除, 就会"断链". 可以链接目录.
2. 硬链接, 相同的inode, 即使源文件被移除, 链接文件也不会受影响, 内容还是可以被访问到. 不能链接目录.
## AI答案
```markdown
- **软链接**：软链接是一个独立文件，有自己的 inode，里面保存目标文件的路径。目标文件被删除后，软链接会变成悬空链接。软链接可以链接目录，也可以跨文件系统。
    
- **硬链接**：硬链接和原文件名指向同一个 inode，相当于给同一个文件增加一个名字。删除其中一个文件名，不影响通过其他硬链接访问文件。硬链接通常不能链接目录，也不能跨文件系统。
```

# 4、环境变量有什么用？什么时候需要使用到环境变量？如何配置环境变量？
## 答:
环境变量的作用: 存放系统配置文件 程序/命令搜索路径
什么时候用到环境变量: 执行命令 调用动态库文件
配置环境变量: 临时配置-export 变量=值. 永久配置: 用户级别-~/.bashrc; 系统级别: /etc/profile

## AI答案
```markdown
环境变量是操作系统提供给进程的一组 变量名=值 的运行环境信息，程序可以通过环境变量获取配置并改变自己的行为。
常见场景包括：通过 PATH 指定命令搜索路径，通过 LD_LIBRARY_PATH 指定额外的动态库搜索路径等。
临时配置可以使用：
export 变量名=值
例如：

用户级的长期配置可以写入 ~/.bashrc，系统级配置可以根据登录环境写入 /etc/profile 等配置文件。
```

# 6、GDB调试一般用于排查什么问题？GDB的调试流程？
## 答:
gdb一般用于函数内执行问题, 调用问题, 执行过程中的变量值问题
gdb调试流程: 
1. gcc 编译时带`-b` 选项生成可执行文件
2. `gdb main`
3. `run`
4. `list` 查看代码
5. `b 10`在第十行带断点
6. `info b` 查看断点信息
7. `bt` 查看调用栈
8. `print a` 打印a变量值
9. `continue` 执行下一个断点, 或者到程序执行结束
10. `step` 执行下一步
11. `exit` 退出

**`-g` 是`gcc`编译增加调试信息的选项, 不是`-b`!!!**
**`quit` 是退出的指令, 而不是`exit`**


## AI推荐答案
```markdown
GDB 主要用于调试程序运行过程中出现的问题，例如程序崩溃、段错误、逻辑错误、函数调用异常等。可以通过 GDB 设置断点、单步执行、查看变量值和函数调用栈，从而定位问题。
基本调试流程：
1. 编译时通过 -g 加入调试信息：gcc -g main.c -o main
2. 启动 GDB：gdb main
3. 使用 list 查看源代码
4. 使用 break 10 或 b 10 设置断点
5. 使用 run 启动程序
6. 程序停在断点后，可以使用 print a 查看变量
7. 使用 next 单步执行且不进入函数，使用 step 单步执行并进入函数
8. 使用 bt 查看函数调用栈
9. 使用 info breakpoints 查看断点
10. 使用 continue 继续运行到下一个断点或程序结束
11. 使用 quit 退出 GDB
```

# 7、段错误是什么意思？产生段错误的原因有哪些？
## Answer:
段错误是操作内存产生的错误
原因一般有: 访问越界(比如数组的访问越界, 访问了不属于程序的内存地址). 

## AI Answer:
```markdown
段错误（Segmentation Fault）是程序访问了无权访问的内存区域，操作系统检测到非法内存访问后终止程序的一种错误。
常见原因包括：空指针或野指针访问、数组或内存越界、访问已经释放的内存、修改只读内存，以及递归过深导致栈溢出等。
出现段错误后，可以使用 GDB 调试，通过 bt 查看函数调用栈，再结合 print、list 等命令定位具体问题。
```

# 8、标准IO与文件IO的区别有哪些？
## Answer:
标准IO: 由C语言库函数提供, 属于应用层调用, 可移植性高, 通过操作流(stream)来实现输入/输出操作. 有自己的缓存机制, 可以避免频繁的进行硬件层的操作.
文件IO: 直接执行由系统提供的IO函数来数显输入/输出操作, 交给内核直接操作硬件层数据. 是在内核层调用. 适合大块的文件输入输出, 不适合频繁且小数据的文件输入输出.

## AI Answer:
```markdown
标准 IO 由 C 标准库提供，例如 fopen、fread、fwrite、fclose，主要通过 FILE * 和流 stream 操作数据。标准 IO 可移植性较好，并且通常具有用户态缓冲机制，可以减少频繁的系统调用，提高 IO 效率。
文件 IO 在 Linux 中通常指通过 open、read、write、close 等系统调用接口操作文件，主要使用文件描述符 fd。调用这些接口时会通过系统调用进入内核完成相应操作。
两者的主要区别在于：标准 IO 属于 C 标准库接口，操作对象主要是 FILE *；文件 IO 更接近操作系统提供的接口，操作对象主要是文件描述符 fd。标准 IO 通常带有用户态缓冲，因此可移植性和小数据频繁读写方面通常更方便；文件 IO 更接近操作系统底层接口，控制更加直接。
```
# 9、标准IO的缓冲区有哪些？作用于哪里？刷新条件有哪些？为什么需要用到缓冲区？

## Answer
缓冲区有哪些: 行缓存, 块缓存; 无缓存
行缓存: `stdin` `stdout`
块缓存: `fopen fread fwirte`
无缓存: `strerr`

作用于哪里: 
行缓存一般用于终端的标准输入输出
块缓存一般用于文件的读写
无缓存: 用于标准错误. (我的理解, 有错误就需要马上报错, 不能缓存)

为什么需要缓冲区:
避免频繁的进行用户态 内核态的切换, 减少系统开销. 减少频繁对硬件层的直接操作.

刷新条件:
程序报错退出
缓存区满
输入/输出切换
程序执行完
fflush手动刷新缓存

行缓存:
遇到换行符也会刷新缓存区.

## AI Answer
```markdown
标准 IO 有三种缓冲方式：全缓冲、行缓冲和无缓冲。
全缓冲通常用于普通文件 IO，数据先存入缓冲区，缓冲区满后再进行实际的 IO 操作。
行缓冲通常用于连接终端的标准输入输出流，例如终端上的 stdin、stdout，遇到换行符时通常会触发输出刷新。
无缓冲的典型代表是 stderr，数据需要及时输出。
常见刷新条件包括缓冲区满、行缓冲输出遇到换行符、调用 fflush()、调用 fclose() 以及程序正常结束等。
使用缓冲区的主要目的是将多次小数据 IO 合并起来，减少 read/write 等系统调用的次数，从而减少系统调用和用户态、内核态切换带来的开销，提高 IO 效率。
```
# 10、动态库和静态库的区别？各有什么好处？
## Answer
静态库: 直接插入到程序中
动态库: 不直接插入到程序中, 程序需要调用时再去库中查找调用

好处:
静态库: 不对动态库存在依赖, 移植到其他设备可以直接运行.
动态库: 不额外产生空间占用, 如果多个程序都用的话, 节省内存空间. 动态库更新后, 所有程序的功能都会随之更新, 不需要重新编译程序.

## AI Answer
```markdown
静态库在链接阶段，会将程序需要的库目标代码复制到最终的可执行文件中。Linux 下通常以 .a 结尾。优点是程序运行时对相应动态库的依赖较少，部署比较方便；缺点是生成的可执行文件通常较大，多个程序使用相同静态库时会存在代码重复。
动态库的代码通常不会复制到可执行文件中，程序运行时由动态链接器加载所依赖的共享库。Linux 下通常以 .so 结尾。优点是多个程序可以共享同一个动态库，能够减少磁盘和内存中的重复代码，并且在 ABI 兼容的情况下，升级动态库通常无需重新编译程序；缺点是程序运行时依赖对应动态库，如果库缺失或版本不兼容，程序可能无法正常运行。
```
