
### 8分题
1. 进程与线程的区别，以及实际什么场景运用它们  
进程是资源分配的最小单位. 线程是任务执行的最小单位.
进程之间不会有共享的内存空间, 同进程下的线程有共享的内存资源, `PID`等
进程至少有一个线程(主(main)线程). 

运用场景: 
```
进程: 资源互不影响, 没有直接关系(各个应用之间, 浏览器浏览页之间). 一个进程崩溃不会影响其他进程
线程: 分任务执行, 有着共同的资源需要管理. 一个线程的崩溃可能会影响其他线程的执行
```
1. fork 函数如何使用？为何fork的返回值如此设计？  
```
pid_t pid = fork();
// 一次调用, 两次执行.
失败直接返回-1, 
成功返回两个值, 一个值大于零, 代表父进程, pid值为子进程id
一个值等于零, 代表子进程

为什么这么设计:
父进程获得子进程, 方便记录, Linux也没有提供获取子进程id的接口函数, 通过pid传递记录
子进程可以通过getpid获取自己pid, 以及getppid获取父进程id
通过这样的设计也好程序做判断 ==0 和 > 0来区分父进程 子进程

```
1. 什么是虚拟地址？有什么作用？
```
虚拟地址是进程执行时,分配的地址空间. 再有cpu和mmu来进行实际物理地址的映射
作用: 可以做到进程之间内存的访问隔离, 对不同进程, 也可以有更好的内存管理分配, 避免浪费.
```

### 10分题
1. 简述写实拷贝技术 与 计数技术  
```
fork后的父子进程, 暂时会映射到同一个物理内存中, 只有双方有一方对内存中数据有修改才会拷贝一份出来, 避免内存的浪费
计数: 进程中的引用计数也就是利用标准/文件IO的函数,引用文件, 每增加一次引用就会+1, 如果内核发现没有进程 / 文件引用就会进行回收, 节省内存空间.
这两个技术都是合理节省内存, 在适当的时候增加 或者 释放内存资源.
```

### 15分题
1. 线程同步实现方法及代码编写，两个线程交替打印AB。（应用层常考）
```C

sem_t sem1,sem2;
void * thread_1(void * arg){
	while(1){
		// P操作
		sem_wait(&sem1);
		printf("A");
		//V操作
		sem_post(&sem2);
	}
	
	
	return NULL;
}

void * thread_2(void * arg){
	while(1){
		// P操作
		sem_wait(&sem2);
		printf("A");
		//V操作
		sem_post(&sem1);
	}
	return NULL;
}


main(){
	sem_init(&sem1, 0, 1);
	sem_init(&sem2, 0, 0);
	
	pthread_t tid1, tid2;
	pthread_create(&tid1, NULL, thread_1, NULL);
	pthread_create(&tid2, NULL, thread_2, NULL);
	
	
	pthread_join(tid1, NULL);
	pthread_join(tid2, NULL);
	
	sem_destroy(&sem1);
	sem_destroy(&sem2);
	
	return 0;
	
}
```
1. 死锁是如何产生的？怎么避免死锁的产生  
```
多个互斥锁, 在多个线程中使用中, 因为引用顺序的问题, 产生了不可能等待到的情况.
比如 A锁 B锁. 线程1 先锁了A 后续锁B.线程2 先锁了B 后锁了A. 后续线程1 线程2 都会停止.

避免: 资源锁按照顺序进行, A->B. 避免多个资源锁的同时调用.
```

进程先预设了多个线程执行统一的任务, 避免了线程重复的创建销毁, 同时限制了同一时间处理的任务量.
